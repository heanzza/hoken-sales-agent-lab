法人営業AIエージェント・ラボ

「出力精度①〜⑤」だけを測るPoCは、なぜ不完全なのか——。ビジネスユーザーが30分・ノーコードで、精度の天井を決めるContext(用語・関係)、統制、本番化を手を動かして体感するファシリテーター台本。

対象ビジネスユーザー（営業・企画） 所要約30分 形式UI操作のみ・コード記述なし 題材法人営業（企業向け提案） 環境Databricks / jp-fsi
このハンズオンの狙い

「相手の土俵」から、論点を動かす

他社提案の営業AI PoCは、営業プロセス ①ターゲティング ②企業分析 ③課題抽出 ④商談準備 ⑤提案書 の出力精度を測ることに主眼を置いています。しかし精度の天井を決めるのは、モデルではなく企業文脈（Context）です。今日は、同じ質問でもContextの有無で答えが変わることを体感し、統制と本番化まで含めて「測るべきこと」を明らかにします。

相手の土俵

精度①〜⑤

プロセスごとの出力精度・事実誤認率。モデル勝負に閉じてしまい、精度の天井そのものは動かない。

動かす論点 ①

Context＝精度の天井

用語の一貫性（Unity Catalog Pages）と、エンティティの関係（Ontology）。ここが整って初めて精度が上がる。

動かす論点 ②

統制と本番化

Unity AI Gatewayによる統制・コスト、Agent Bricksによる本番運用。PoCで測らなければ片手落ち。

今日の主張 —— 「精度の天井を決めるContext層と、本番運用を測らないPoCは不完全。」 精度は入口であって、勝敗を分けるのはその先の Context・統制・本番化である。

用語（Pages）— 精度の天井が動く瞬間

同じ質問を「素のGenie」と「用語集ありGenie」で比較する
6:00 → 12:00
目的

このハンズオンの山場。社内用語「退準（退職金準備）」を含む同じ質問を2つのエージェントに投げ、答えが変わることを体感する。精度を決めるのはモデルではなく用語の一貫性だと腹落ちさせる。

操作
  1. まず 【Before】素のGenie（用語集・文脈なし）を開き、下の質問を投げる。
  2. 次に 法人営業アシスタント（用語集あり）で、まったく同じ質問を投げる。
  3. 2つの答えを並べ、どちらが「深耕」として正しいかを議論する。
質問
退準の提案余地がある担当企業を、保有ANPの大きい順に3社教えて
結果の対比
Before：素のGenie

「退準」を理解できず、メモの文字列をあいまいに一致させて全契約のANPを合計 → 全国製薬…など、根拠のずれた企業を提示。

After：用語集あり

退準＝退職金準備プランと解釈し、それが未提案の企業だけを抽出 → 大阪製作所・九州製作所・九州システムズ。深耕として正しい。

深掘り

続けて「用語そのもの」を聞き、用語集が引かれていることを見せる。

「GLTD」とは何ですか? また就業不能に関心を示している商談はありますか?
結果

GLTD＝団体長期障害所得補償保険（Group Long Term Disability）と定義を返し、就業不能に関心のある商談（みらいテック等）まで結合して提示。

話すこと
勝ち筋トーク

「モデルは同じ。違うのは、会社の言葉（用語・KPI・ドメイン定義）を一貫して与えているかどうかだけです。用語の揺れ＝“メトリックドリフト”を放置すると、③課題抽出も⑤提案書も、この土台の上でブレ続けます。精度の天井は、ここで決まります。」

勝ち筋
#5 用語・KPI一貫性#4 文脈基盤
製品名

この用語・定義・KPIの標準化は、Databricks では Unity Catalog Pages（旧称: ビジネスグロッサリ。現在は Domains＋Pages＋Metric Views＋Certification として semantics/Discover に統合）で整備します。社内用語集は SQL テーブルにせず、Pages を真実の源とします（Pages 未有効の環境では、その内容を Genie の Instructions に取り込んで同等効果を再現）。

関係（Ontology）— エージェントが横断できる理由

企業・契約・商談・商品の“つながり”を1問で辿る
17:00 → 23:00
目的

Genie Agent が“なぜ”企業を軸に横断照会できるのか——その答えが関係（Ontology）。単一表では出せない「企業360度の状況」を1問で引き出し、関係（PK/FK）＋セマンティック層（Metric View）＋企業360ビューがその正体だと示す。

操作
  1. 法人営業アシスタントで、深耕の主役企業について横断質問を投げる。
  2. 1つの答えに「契約・商談・未提案・課題」が揃うことを確認する。
質問
九州建設株式会社の契約状況・直近の商談・未提案商品をまとめて教えて
期待
結果

契約 14件（有効12件）、保有ANP 2,788万円、平均13ヶ月継続率 0.905、直近商談はクロージング（事業承継を見据えた経営者保険を提案）、未提案商品は事業保障プラン・法人向け医療保険——を1回で提示。

話すこと
勝ち筋トーク

「企業・契約・商談・商品は、バラバラの表ではなく“関係”でつながっています。この関係＝Ontologyがあるから、Genie Agentは担当者が頭の中でやっていた突き合わせを一気に肩代わりできる。しかも権限（RBAC）はソース側を継承するので、見てよい人にしか見えません。」

進行のコツ

講師メモ

  • STEP 2 が主役。Before と After はまったく同じ質問文を使うこと。違いが「モデル」ではなく「Context」だけであることが伝わる。
  • 30分厳守。各ステップの質問は原則1つに絞る。深掘りは時間が余ったときのみ。
  • コードは見せなくてよい。Genieの「SQLを見る」は開かなくて構わない。ただし技術に懐疑的な参加者がいれば、生成SQLを見せると「ちゃんと未提案だけ絞っている」ことが刺さる。
  • 主役企業。深耕＝九州建設株式会社、新規開拓＝みらいテック株式会社。別企業で試したい場合も、企業360ビューにある96社ならどれでも動く。
  • 相手の土俵に戻さない。「①〜⑤の精度は何%出ますか?」と聞かれたら、「精度はモデルとContext次第。今日の主眼は、その精度の天井を上げるContextと、本番で使い続ける統制です」と論点を戻す。
